# Weblyfe Design Philosophy

## Core rule

Design from evidence, not taste memory. Before implementation, lock the direction from real references, client constraints, brand assets, and conversion goals. Then build and verify in the browser.

## Operating loop

1. Research first: styles for taste, screens for UI patterns, flows for journeys, plus competitors and brand assets.
2. Reference-lock: choose one dominant direction; preserve signature traits; borrow only narrow details; reject averaged safe design.
3. Build with a point of view: shadcn/ui is the accessible base, not the finished design; Magic UI is purposeful polish; generated media is only for stronger brand/conversion moments.
4. Conversion structure beats visual noise: obvious next step above the fold, trust immediately after the hero, real proof and objection handling.
5. Browser verification is part of design: build, mobile, console/network, CTA flow, metadata/Open Graph, live URL.

## Weblyfe house style

- Luxury through restraint: fewer colors, better spacing, stronger hierarchy.
- Authority first: credentials, proof, and specificity before generic features.
- Story over specs: explain why the thing matters, not just what it contains.
- Premium imagery: real assets first; generated assets only when they support the brand and do not carry critical text.
- Light theme by default for client sites unless the brand calls for dark. Weblyfe AI/Appie pages can use dark emerald and gold as a brand-native exception.
- No production emojis unless explicitly brand-approved.

## Generated media rule

Generated images are supportive assets, not truth sources. If image text or logos are imperfect, keep critical copy in HTML and use the generated image as mood/supporting proof.
